# Certificate authority (`kind: CertificateAuthority`)

**CertificateAuthority** registers a **CA (certificate authority)** in the Controller **PKI catalog** for the ECN namespace. Leaf **`kind: Certificate`** resources are signed by an existing CA (or use **`ca.type: self-signed`** on the leaf — see [Certificate](../certificate/README.md)).

This is **namespace-scoped Controller PKI**, not the same as **global Router/NATS site CAs** on [control plane deploy](../controlplane/remote/securing-cluster.md) (`routerSiteCA`, **`SiteCertificate`** blocks). Those upload TLS into PoT Secrets and import with **`type: direct`** using fixed names like `router-site-ca`.

## What gets deployed

1. Controller reachable.
2. CLI unmarshals **`spec`** → **`CreateCA`**.
3. If the name already exists → **fail** (no CA update; delete and recreate).

## CA types (summary)

| `spec.type` | Meaning |
|-------------|---------|
| **`self-signed`** | Controller generates a new CA (set **`subject`**, optional **`expiration`** days) |
| **`direct`** | Import from a **PoT Secret** (`spec.type: tls`, base64 PEM in **`data`**) |
| **`k8s-secret`** | Import from a **Kubernetes Secret** on the control plane cluster |

Details, naming rules, and examples: [schema.md](schema.md).

## Prerequisites

| Type | Before deploy |
|------|----------------|
| **`self-signed`** | None |
| **`direct`** | **`kind: Secret`** with TLS base64 **`data`**; **`metadata.name`** = CA name |
| **`k8s-secret`** | K8s secret present; name alignment per [schema.md](schema.md) |

## Deploy

```bash
potctl deploy -f ca.yaml -n my-ecn
potctl get certificates -n my-ecn
potctl describe certificate ecn-root-ca -n my-ecn
potctl delete certificate ecn-root-ca -n my-ecn   # prompts for CA delete
```

`describe` output includes **private keys** — handle as confidential.

## Typical flows

**New ECN CA (generated by Controller):**

```text
CertificateAuthority (self-signed) → Certificate (leaf, ca.type direct + secretName)
```

**Bring-your-own CA PEM:**

```text
Secret (type tls, base64 data) → CertificateAuthority (direct) → Certificate (leaf)
```

## Deploy order

**CertificateAuthority** after **Secret** (when importing) and before **Certificate** in multi-doc YAML. See [operator index](../README.md#ecn-resource-deploy-order).
